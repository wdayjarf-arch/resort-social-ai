# Resort Social AI — Phase 2 Foundation

A foundation scaffold for a multi-organization, multi-property social management platform.

## Included

- FastAPI app with liveness/readiness endpoints
- Pydantic Settings validation
- SQLAlchemy 2 models for organizations, brands, properties, users, memberships, social accounts, encrypted OAuth credentials, and audit logs
- Organization-scoped composite foreign keys on tenant-owned relationships
- Fernet token encryption helper
- Alembic initial migration
- PostgreSQL/pgvector, Redis, API and Celery worker via Docker Compose
- Small automated tests

## Run locally

1. Copy `.env.example` to `.env`.
2. Change `POSTGRES_PASSWORD` and make the password in `DATABASE_URL` match it.
3. Generate a Fernet key:
   ```bash
   python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
   ```
   Paste the result into `TOKEN_ENCRYPTION_KEY`.
4. Start services:
   ```bash
   docker compose up --build
   ```
5. Check:
   - `http://localhost:8000/health/live`
   - `http://localhost:8000/health/ready`
   - `http://localhost:8000/docs`

## Important security boundaries

This scaffold is not a complete production deployment. It intentionally does not expose tenant CRUD endpoints or a public login endpoint. Before public deployment, implement and verify OIDC/session authentication, authorization dependencies on every tenant endpoint, secret-manager integration, TLS, backups, alerting, provider OAuth state/PKCE as appropriate, Meta webhook signature verification, and security review.

`TOKEN_ENCRYPTION_KEY` is a single-key starter design. For production, use a managed KMS/envelope-encryption strategy and a key rotation plan. Keep keys out of source control and container images.

AI auto-replies are disabled by default. Keep the default fail-closed policy until knowledge-base matching, risk classification, approvals, audit events, and outbound provider permissions are implemented and tested.

## Migrations

Initial migration runs automatically in the API container. To generate future migrations:
```bash
docker compose exec api alembic revision --autogenerate -m "describe change"
docker compose exec api alembic upgrade head
```

Review every autogenerated migration before applying it in production.
